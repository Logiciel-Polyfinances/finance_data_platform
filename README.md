# Finance Data Platform

A batch financial data platform: fetch data from external providers, land it
raw (Bronze), clean/normalize it (Silver), load serving-ready tables into
Postgres (Gold, on Supabase), and serve them through a FastAPI. Runs fully
serverless on AWS (Lambda + Step Functions + EventBridge Scheduler + API
Gateway), Bronze/Silver on S3.

```
external API -> Bronze (S3, raw JSON) -> Silver (S3, Parquet) -> Gold (Postgres) -> API
```

## What's implemented

| Data | Source | Pipeline | Schedule (America/Montreal) |
| --- | --- | --- | --- |
| Daily prices (OHLCV) | Yahoo Finance | `run_prices.py` | weekdays 16:05 |
| Macro/FX series | FRED | `run_macro.py` | Monday 06:00 |
| Fundamentals (XBRL) | SEC EDGAR | `run_fundamentals.py` | Monday 07:00 |
| Fundamentals (non-US) | Yahoo Finance | `run_yf_fundamentals.py` | Monday 08:00 |
| Ticker <-> FIGI mapping | OpenFIGI | `run_map_figi.py` | Monday 08:00 |
| Fundamental ratios (derived) | Gold | `run_fundamental_ratios.py` | Monday 09:00 |
| Risk metrics (derived) | Gold | `run_metrics.py` | daily 03:00 |
| Historical backfill | Yahoo Finance | `backfill_prices.py` | on-demand only |
| New ticker onboarding | Yahoo Finance | `run_register_ticker.py` | on-demand only |

Pipelines live in `src/orchestration/pipelines/`. Each follows the same
shape (`bronze_ingest -> silver_transform -> gold_load`), runs a quality
check (`src/transformers/quality/checks.py`) before the Gold upsert, and is
wrapped in an `ingestion_runs` row for observability. See
[docs/STRUCTURE.md](docs/STRUCTURE.md) for where everything lives.

## API

`src/main.py` — FastAPI; on AWS a Lambda behind API Gateway (HTTP API) via
Mangum (`src.main.handler`), locally `uvicorn` (see `dockerfile`). The data API
is versioned under `/v1`; `/health` and `/admin` stay unversioned.

| Route | Scope | What |
| --- | --- | --- |
| `GET /health` | none | DB connectivity check, no auth (for Docker/LB healthchecks) |
| `GET /v1/instruments`, `GET /v1/instruments/{ticker}` | read | registered tickers |
| `POST /v1/instruments` | write | register a ticker + kick off an initial backfill |
| `POST /v1/instruments/{ticker}/refresh` | write | force a re-fetch of an existing ticker (prices and/or fundamentals) |
| `PATCH /v1/instruments/{ticker}/scheduled` | write | toggle the daily auto-ETL on/off |
| `GET /v1/instruments/{ticker}/figi` | read | OpenFIGI candidates for a ticker |
| `GET /v1/prices/{ticker}` | read | daily OHLCV, filterable by `start`/`end` |
| `GET /v1/fundamentals/{ticker}` | read | XBRL facts, filterable by `concept` |
| `GET /v1/macro/{series}` | read | FRED series, filterable by `start`/`end` |
| `GET /v1/runs`, `GET /v1/runs/{run_id}` | read | ingestion run status (observe async backfills) |
| `GET/POST/DELETE /admin/api-keys` | admin | key management (env master key only) |

**Auth & scopes.** All routes except `/health` require an `X-API-Key` header
whenever `ENV != local` (see `src/api/deps.py`). The env master `API_KEY`
authenticates as admin (full access, no rate limit) and is the only key that
manages `/admin/api-keys`. Hand consuming apps their own DB-managed keys
(`POST /admin/api-keys`), each scoped `read` (serve Gold data) and/or `write`
(trigger ingestion via register/refresh) — new keys default to read-only. On AWS
the master key is generated by Terraform into SSM:
`aws ssm get-parameter --with-decryption --name /finance-data-platform/app/api-key`.

**Rate limits.** On AWS there is no Redis (cost): API Gateway throttles the
whole API (default 20 req/s, burst 50) and `POST /v1/instruments` /
`.../refresh` separately (1 req/s, burst 5 each), answering `429` without invoking the Lambda — see
`infra/api_gateway.tf` / `variables.tf`. These are API-wide, not per key. In
the local docker stack (with Redis) the per-key limiter still applies
(`RATE_LIMIT_PER_MINUTE`, `RATE_LIMIT_WRITE_PER_MINUTE`); it fails open
without `REDIS_URL`.

**Idempotence.** `POST /v1/instruments` and `.../refresh` take a short-lived
per-ticker dedup lock (Redis; fails open, so local only), so a
duplicate/concurrent trigger won't fan out a second backfill. A refresh whose
datasets are all already in flight returns `409`; otherwise it returns `202`
with the jobs it kicked off — poll `GET /v1/runs` for completion/status. On AWS
the backfills are Step Functions executions (`fdp-prices-daily`, `fdp-fanout`);
locally they run in-process.

List endpoints support `limit`/`offset` and return the total row count in an
`X-Total-Count` header, and are cached in Redis for a short TTL when Redis is
configured (local only; fails open otherwise).

## Internal UI

A React + Vite app (`frontend/`) served at `/app` — add/toggle tickers and
browse prices/fundamentals/macro/FIGI tables. It's same-origin with the API
(no CORS involved) and reads an API key from a browser field if one is
configured. Meant as an internal admin tool, not a public-facing app — the
key is visible in the page's JS if you set one.

```bash
cd frontend
npm install
npm run dev        # dev server on :5173, proxies API calls to :8000
npm run build       # -> frontend/dist, served by FastAPI at /app
```

`src/main.py` mounts `frontend/dist` as static files; the API still boots
(with a logged warning) if the frontend hasn't been built. Both `dockerfile`
(local) and `Dockerfile.lambda` (AWS) build it in a Node stage — on AWS the UI
is served by the API Lambda at `<api_url>/app/`.

## Setup

```bash
uv sync
cp .env.example .env   # fill in DATABASE_URL, BUCKET_ID, API keys
uv run alembic upgrade head
cd frontend && npm install && npm run build && cd ..
uv run uvicorn src.main:app --reload
```

Then open http://localhost:8000/app/ for the internal UI, or http://localhost:8000/docs for the API's interactive docs.

Required env vars (see `src/core/config.py` for the full list):

- `DATABASE_URL` — Postgres connection string
- `BUCKET_ID` — S3 bucket for Bronze/Silver
- `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` — S3 credentials
- `FRED_API_KEY`, `OPENFIGI_API_KEY` — provider API keys
- `API_KEY` — required once `ENV != local` (the API fails closed without it)
- `REDIS_URL` — optional, enables response caching (local only)

`npm run local` (`docker compose -f docker-compose.local.yml up`) runs a fully
local stack: Postgres, MinIO (S3), Redis and the API; migrations run
automatically on container start. There is no scheduler locally — run
pipelines by hand (below).

## Running a pipeline

```bash
uv run python -m src.orchestration.pipelines.run_prices          # one ticker/day
uv run python -m src.orchestration.pipelines.backfill_prices --symbols AAPL,MSFT --start 2015-01-01
uv run python -m src.orchestration.pipelines.run_register_ticker AAPL
```

On AWS the schedules above run the pipelines against every ticker flagged
`is_active` + `is_scheduled` in `universal_instruments` (prices/fundamentals/
figi, filtered per source by `src/orchestration/universe.py`) or
`FRED_COLUMN_SERIES` (macro).

## Deployment (AWS)

Everything lives in `infra/` (Terraform, state in the shared
`polyfinances-terraform-state-437848352148` bucket, key
`finance_data_platform/terraform.tfstate`), deployed by GitHub Actions through
the `GitHubActionsAdmin` OIDC role:

- `ci.yml` — ruff + unit tests on every push/PR.
- `plan.yml` — on PRs to `master`: builds the Lambda image (no push),
  `terraform fmt/validate/plan`.
- `deploy.yml` — on push to `master`: ensure the ECR repo → build & push the
  image (tag = commit SHA) → `alembic upgrade head` against Supabase's
  **session pooler** (5432, URL read from SSM) → `terraform apply` → smoke-test
  `GET /health`.

| Piece | AWS |
| --- | --- |
| API | Lambda `fdp-api` (container image) behind API Gateway HTTP API |
| Daily prices | Step Functions `fdp-prices-daily` → Lambdas `fdp-get-tickers`, `fdp-prices-{bronze,silver,gold}` |
| SEC / yfinance fundamentals, OpenFIGI | Step Functions `fdp-fanout` (Map, bounded concurrency) → `fdp-sec-fundamentals`, `fdp-yf-fundamentals`, `fdp-figi` |
| FRED macro/FX | Step Functions `fdp-fred-macro` (Map, one run per series) → `fdp-fred-series`, `fdp-fred-macro` |
| Ratios, metrics | Lambdas `fdp-fundamental-ratios`, `fdp-metrics`, invoked directly |
| Schedules | EventBridge Scheduler group `fdp`, timezone America/Montreal (`schedules_enabled` pauses all) |
| Bronze/Silver | S3 `fdp-data-lake-437848352148` (`bronze/`, `silver/` prefixes) |
| Gold | Supabase Postgres, via the **transaction pooler** (6543) from Lambda |
| Secrets | SSM `/finance-data-platform/*`, resolved at cold start (`src/core/ssm.py`) |

Every function runs the same image (`Dockerfile.lambda`): the dependency
closure (pyarrow, polars, pandas, yfinance, matplotlib…) is ~530 MB, over the
250 MB zip limit. No Redis, RDS, NAT or always-on compute: expected cost
≈ $0–2/month.

One-time manual step: the vendor keys aren't managed by Terraform (so they
never land in state). Create them once:

```bash
aws ssm put-parameter --type SecureString --name /finance-data-platform/app/fred-api-key --value <key>
aws ssm put-parameter --type SecureString --name /finance-data-platform/app/openfigi-api-key --value <key>  # optional
```

### Manual runs & backfills

Registering or refreshing a ticker via the API starts its backfills itself.
To run one by hand, use the Step Functions console or the CLI:

```bash
# price history for one or more tickers (any date range)
aws stepfunctions start-execution --state-machine-arn "$(terraform -chdir=infra output -raw prices_daily_state_machine_arn)" \
  --input '{"symbols_override": "AAPL", "start_dt": "2015-01-01", "end_dt": "2026-09-25"}'

# SEC fundamentals for specific tickers (same for yf-fundamentals / figi)
aws stepfunctions start-execution --state-machine-arn "$(terraform -chdir=infra output -raw fanout_state_machine_arn)" \
  --input '{"mode": "us_only", "run_function": "fdp-sec-fundamentals", "tickers_override": "AAPL", "max_concurrency": 1}'

# FRED series (all of FRED_COLUMN_SERIES without an override)
aws stepfunctions start-execution --state-machine-arn "$(terraform -chdir=infra output -raw fred_macro_state_machine_arn)" \
  --input '{"series_override": "cpi"}'
```

Without overrides, `fdp-prices-daily` loads the previous weekday (same as the
old DAG's `ds`) for the whole scheduled universe.
